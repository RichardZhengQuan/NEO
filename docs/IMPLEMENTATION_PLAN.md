# Implementation plan

The foundation is done: `@neo/protocol` (contracts) and `@neo/storage` (SQLite) are implemented and tested. Every other package has a **frozen public API** in its `src/index.ts`: stubs that compile and throw "not implemented". The work packages (WPs) below replace those stubs in parallel. Each WP owns exactly one directory.

## Rules for every work package

1. **Stay in your directory.** Do not edit other packages, the root config, or `packages/protocol`. If a contract seems wrong or missing, work around it locally and report it.
2. **Keep the frozen signatures.** Exports in `src/index.ts` keep their names and types. You may add exports. Split the implementation into modules (`src/*.ts`) and re-export from `index.ts`.
3. **No dependency changes.** Don't edit `package.json` dependencies or run `pnpm install/add`. Everything you need is already installed (see each package.json). Report anything missing instead.
4. **Conventions.** TypeScript strict, ESM, **relative imports end in `.js`** (`import { x } from './x.js'`). Use `import type` for types (`verbatimModuleSyntax`). Throw `NeoError` across package boundaries. Inject `Clock` and `Logger` instead of calling `Date.now()` and `console` in library code. No `any` in public types.
5. **Tests.** vitest, colocated `src/**/*.test.ts(x)`, fully **offline** and deterministic (inject clocks; fake fetch/WebSocket; in-memory SQLite via `openNeoDatabase(':memory:')`). Packages that depend on not-yet-implemented siblings use fakes that implement the protocol interfaces.
6. **Checks.** Run them from your package directory: `npx tsc -p tsconfig.json --noEmit` and `npx vitest run` (apps: also `npx vite build` for web). Typecheck follows sibling sources; **errors reported in files outside your directory belong to another WP**. Ignore them and re-run later.
7. **Quality bar.** This is the product, not a prototype. Readable modules, comments where intent isn't obvious (match the existing style), robust error handling, no dead code, no TODOs left for core behavior.

## Work packages

### WP-providers: `packages/providers`
Spec: [PROVIDERS.md](PROVIDERS.md). Implement `createProvider`, `createProviderRegistry`, `parseSSE`, `MockProvider` + `defaultMockScript`, and adapters for Anthropic (official `@anthropic-ai/sdk`), OpenAI/OpenAI-compatible/Ollama (fetch) and Gemini (fetch).
Tests: SSE parser (chunk boundaries, CRLF, multi-line data, comments); each adapter against a **fake fetch** replaying recorded-style SSE fixtures (text, reasoning, tool-call argument streaming across chunks, usage, stop reasons, 401/429/500 mapping, retry before first byte, abort); request mapping (messages/tools/images/tool results; reasoning replay only for same model; strip-and-retry on Anthropic signature error); registry resolve/disable/upsert/remove; mock script intents and memory-extract JSON.
Done when: all tests pass; an explicitly injected `mockScript` streams a deterministic test reply offline. User configuration and APIs never enable mock providers.

### WP-memory: `packages/memory`
Spec: [MEMORY.md](MEMORY.md). Implement the schema, the vector cache, `HashingEmbedder`, `createProviderEmbedder`, recall (seeds + spreading activation + scoring + MMR + reinforcement + Hebbian), observe (LLM extraction with lenient JSON parsing and heuristic fallback, filters, dedupe, supersede, entities, links), remember/search/get/update/forget/findForForget/link/unlink/graph/consolidate/journal/stats/export/import/policy/onChange, and `retention`, `cosineSimilarity`, `heuristicExtract`.
Tests: retention and stability math; recall finds a fact through an entity link (spreading activation) that shares no words with the query; sensitive filtering; dedupe merges near-duplicates; supersede keeps history; credential filters; consolidation archives faded memories (fake clock + 1 year), prunes edges, links similar nodes, merges duplicate entities, and abstracts episodes via a scripted fake LLM; export → import round trip; graph query shapes; an observe() with a fake LLM returning messy JSON (code fences, trailing text).
Done when: all of the above pass with in-memory SQLite.

### WP-tools: `packages/tools`

### WP-core: `packages/core`
Spec: [ARCHITECTURE.md](ARCHITECTURE.md) (chat turn, context assembly) + the details below. Depends only on protocol interfaces, so test with fakes (an in-memory ConversationStore and a scripted ChatModel/ProviderRegistry). You may also use `@neo/storage` stores in tests, since it's done; add it to devDependencies only if needed and report it.
- `send`: validate (conversation exists; no turn already running in it → `conflict`; parts are user-input or ui_event). Resolve the model: `input.model ?? conv.model ?? settings.defaultModel ?? first enabled provider with a defaultModel`, else `config_error` ("No AI configured — add one in Settings"). On the first turn, freeze `systemPrompt` (buildSystemPrompt) and `toolset` (non-deny, non-uiOnly tool names; `[]` when the model lacks tool support). Recall (unless incognito or `memory.recall` is false; `allowSensitive = adapter.isLocal || policy.sendSensitiveToCloud`; failures are logged and ignored). Then emit `memory.recalled`. Persist the user message `[context part, ...parts]` and an empty `streaming` assistant message, emit `turn.started`, and return the handle. The loop runs in the background.
- Loop (≤ `agent.maxSteps`; the final allowed step sends `toolChoice: 'none'`): build `ChatRequest` from `toChatMessages(trimmedHistory + current turn)`. Trim from the front to `agent.contextTokenBudget` with `estimateMessageTokens`, always starting at a user message. Use the frozen system prompt and the specs of the frozen toolset (`toolSpec(registry.get(name))` for names that still exist), plus maxTokens/temperature/reasoning from settings and the abort signal. Stream: text → `text.delta` (coalesce into the last text part), reasoning → `reasoning.delta` (a placeholder reasoning part tagged `{provider: adapter.kind, model}`, completed by `reasoning_part` data), tool_call → part + `part.added`. Persist the message at least at each step end (throttled updates while streaming are fine). Models without native tools: `extractInlineUI` on the step's text becomes `ui` parts.
- Tools, in call order: unknown or not-in-toolset → error result; `deny` → error result; `confirm` → a `ToolConfirmation` (`describeCall` or `title`), emit `tool.confirmation` and await `confirm()` or a timeout (`agent.confirmationTimeoutSec`) or cancel. Denied gives the error result "The user declined this action." `always` persists `settings.tools.permissions[name] = 'auto'` and calls `tools.setPermission`. Emit `tool.started`, then `execute` with a full `ToolContext` (`origin: 'model'`). Untrusted outputs go through `wrapUntrusted(name, JSON.stringify(output))`. Each `ui` block passes `validateUIBlocks` and becomes a `ui` part with `id: newId('ui')`. Then add the `tool_result` part (with summary) and emit `tool.finished`.
- End: status `complete` and `message.completed` + `turn.finished`. A NeoError gives status `error` with the error + `turn.failed` (partial parts kept). Cancel gives status `cancelled` + `turn.finished(stopReason: 'cancelled')`. Afterwards, asynchronously: auto-title on the first turn (LLM with `metadata.purpose='title'`, no tools, ≤ 30 tokens; fallback is the first 6 words; then `conversation.updated`), and `memory.observe` unless incognito (emit `memory.written` when anything changed). TurnHandle.events yields this turn's events and ends after the terminal event. `done` resolves with the final message and never rejects.
- `handleUiAction`: find the stored message and ui part, then the action via `collectActions`, the form submit (`FORM_SUBMIT_ACTION_ID` → event with values), or `resolveWidgetAction`. `message`/`event` start a new turn (`ui_event` part). `tool` → permission check (deny → `tool_denied`; confirm is satisfied by the client dialog) → execute with `origin: 'ui'`; for task toggles and reminder snooze/complete, patch the stored widget block best-effort. `link`/`copy` → `{kind:'client'}`.
- `buildSystemPrompt` / `buildContextBlock`: see the excerpts in [GENERATIVE_UI.md](GENERATIVE_UI.md) and [ARCHITECTURE.md](ARCHITECTURE.md). The context block format is `<neo_context>\nnow: 2026-10-10 20:15 Saturday (Asia/Shanghai)\nmemories:\n- [fact] … (id mem_…)\n</neo_context>`, plus an incognito note when relevant.
Tests: a full tool-using turn with a scripted model (text → tool call → result → final text); the event sequence; persistence of interleaved parts; confirmation approve/deny/timeout/always; cancel mid-stream; maxSteps cut-off; the frozen system prompt and toolset across turns (append-only: the second request's messages are a prefix-extension of the first's); front trimming; incognito skips recall/observe; ui actions of each kind; inline UI extraction; model resolution errors; a conflict on concurrent sends.

### WP-server: `packages/server`
Spec: [API.md](API.md) + composition in [ARCHITECTURE.md](ARCHITECTURE.md). Implement `loadConfig` (file + env + overrides, `~` expansion, env-created providers), `EventHub` (replay buffer of 500), `createServices` (composition root, described in the plan section "Server composition" below), `createApp` (Hono routes, zod validation, error mapping, auth middleware with an IP failure limiter, CORS, security headers, SSE turn streaming, WebSocket via `@hono/node-ws`, static web app with SPA fallback), `startServer` (listen, scheduler start, consolidation timer every 15 min checking `intervalHours`, graceful stop), the notifier (notification store → event → web-push with VAPID keys from config or `<dataDir>/vapid.json` generated with `web-push`; 404/410 removes the subscription), and pairing (`POST /devices`).
Tests: `createApp` against **fake services** (real storage stores + fakes for runtime/memory/tools/providers/scheduler) for every route group: auth (missing/invalid/device token, rate limit), validation errors, conversations + send (202 and SSE), ui-action, confirmations, memory routes, reminders/tasks/notes, providers (secret moves into the SecretStore and is never returned), settings patch, tools permission, devices, push, the WebSocket auth + event delivery + subscription filter (start a real server on port 0 for this), static serving + SPA fallback; `loadConfig` precedence.

#### Server composition (`createServices`)
1. `dataDir` = expanded `config.dataDir`, created with mode 0700. `db = openNeoDatabase(<dataDir>/neo.db)` (or `:memory:`). `key = loadOrCreateKey(<dataDir>/key)` (random in memory mode).
2. Stores: settings (on first boot: apply `config.settings` + `timezone` from `Intl.DateTimeFormat().resolvedOptions().timeZone` + `locale` from the env), conversations, secrets, devices, push, providerConfigs.
3. Owner token: `config.server.authToken ?? <dataDir>/token ?? generate` (write 0600). If `devices.verify(token)` fails, create the owner device with it.
4. Providers: registry over supported entries in `[...config.providers, ...providerConfigs.list()]` with `resolveSecret = secrets.get`. Test-only providers and their `mockScript` are injected through explicit server options.
5. Memory: embedder from `settings.embedding` (provider embedder) else `HashingEmbedder(512)`. `llm()` resolves `memoryModel ?? defaultModel ?? first enabled provider default` → `{ model: adapter, name, isLocal }` (null when unresolvable). Policy from settings. `settings.onChange → memory.setPolicy`.
6. Tools: registry with settings permissions + `createBuiltinTools({ stores, memory, webSearch: config.webSearch, allowPrivateNetwork: config.mode === 'local' })` + plugins when enabled. `settings.onChange` syncs permissions.
7. Runtime, EventHub, wiring: runtime events, store onChange (reminder/task/note updated/deleted), memory onChange (`memory.changed`), settings onChange (`settings.updated`). Scheduler `onFire` → notifier (`kind: 'reminder'`, title, body = notes or "It's time", or "Missed while you were away: …" when missed; data `{ reminderId, url: 'neo://reminders/<id>' }`) + `reminder.fired` event.

### WP-ui: `packages/ui`

Follow the rendering guidelines in [GENERATIVE_UI.md](GENERATIVE_UI.md). Use `react-markdown` + `remark-gfm` (no `rehype-raw`). Build the icon set from inline SVG paths (lucide-style, about 60 icons, MIT-compatible originals). Charts are hand-written SVG. MemoryGraphView is a hand-written force simulation on `<canvas>` with a DPR-aware draw, pan/zoom/drag, hover tooltip and keyboard-accessible node list fallback. Ship en + zh-CN dictionaries for all UI strings.
Tests (jsdom + Testing Library): every block type renders (snapshot of key text); action callbacks (message/event/tool/link/copy, confirm prompts, form submit values, widget action ids for task toggle / reminder snooze / memory forget); invalid block fallback; Markdown strips HTML and unsafe links; MessageView with interleaved parts + confirmations; Composer send/shift-enter/cancel; i18n interpolation + fallback.

### WP-web: `apps/web`
The one app UI (web, PWA, desktop, mobile). Vite + React 19 + Tailwind v4 + zustand. `vite.config.ts` (react + tailwind plugins, `resolve.conditions: ['neo-source', 'module', 'browser', 'development|production']`, dev proxy `/api` → `http://127.0.0.1:7777` with ws, `base: './'`), `index.html`, `src/main.tsx`, `src/styles.css` (`@import "tailwindcss"; @import "@neo/ui/styles.css"; @source "../../../packages/ui/src";`), `public/manifest.webmanifest`, `public/sw.js` (push + notificationclick + app-shell cache), and SVG icons.
- Connection bootstrap: the Electron bridge (`window.neoDesktop.getConfig()`), else same-origin `/api/health` + saved token (a `#/pair?token=` hash is accepted and saved), else the Connect screen (server URL + token or pairing link). Persist in localStorage (guarded).
- Onboarding wizard (when `!settings.onboarded`): Choose an avatar (character, background) → Choose your AI (preset cards, key, base URL, Test, model picker from `/models`) → Notifications → Done. Saved `memory` and legacy `persona` steps resume at Notifications; legacy `welcome` resumes at AI. Memory is automatic; sensitive-memory controls and their explanation stay in Settings → Memory. Tone, style, reply language and names grow through conversations and the memory net.
- Screens: Chat (sidebar conversations with search/pin/archive; header with editable title, per-conversation model picker, incognito badge; messages with streaming, confirmations, recalled-memories chip, memory-written notice; Composer with suggestions on empty), Memory (Net graph + detail panel, List with filters, Dream journal + Consolidate now, Stats, Export/Import), Reminders, Tasks, Notes, Settings (Providers & models incl. memory/embedding models, Avatar, Memory policy, Tools permissions, Devices + pairing QR via `qrcode`, Notifications/push, Appearance theme + language, Data/About). `#/settings/persona` remains an alias for Avatar.

- Platform bridges in `src/platform/`: browser (Notification + Web Push subscribe with the VAPID key), electron (`window.neoDesktop`), capacitor (`@capacitor/local-notifications`: schedule the next 64 upcoming reminders and resync on reminder events; `@capacitor/app` deep links).
- Hash routing (`#/chat/<id>`, `#/memory`, …) and `neo://` links mapped to routes. Mobile-first responsive layout (bottom tab bar < 768 px), keyboard shortcuts (⌘K new chat, ⌘/ focus composer), en + zh-CN strings.
Done when: `npx tsc --noEmit`, `npx vitest run` (store/event reducer + bootstrap tests) and `npx vite build` pass.
